# دليل التشغيل والنشر الآمن — V8

## 1. حدود العمل

الحزمة غير منشورة. الهدف الوحيد للنشر لاحقًا هو https://v7.samideveloper.com/ بعد موافقتك. لا تغيّر تطبيق samideveloper.com أو دومينه أو تخزينه. لا تدمج إلى main. ارفع التغييرات إلى فرع مثل `feature/sami-v8` بعد مراجعتها.

## 2. التحضير والبيانات الحالية

الملف المرفق لا يحتوي قاعدة SQLite أو صور العملاء أو أسرار البيئة؛ لا يمكن تضمين بيانات سيرفرك فيه. التطبيق السابق في Docker يشغّل `app:app` وملف قاعدة بياناته الافتراضي `/app/data/site.db`. بعض الملفات القديمة كانت تستعمل `/data/site.db`؛ تحقق من التطبيق الفعلي ومسار التخزين في Coolify أولًا.

- سجّل اسم التطبيق التجريبي، نوع البناء، متغيرات البيئة، مسار الـVolume واسم الـVolume الحقيقي.
- خذ نسخة قبل أي تشغيل لـV8 على بيانات قديمة. سكربت النسخ يحتاج التوقف المؤقت عن الكتابة للحصول على مجموعة متزامنة من القاعدة والمرفقات؛ SQLite backup نفسه متسق حتى لو كانت القاعدة تعمل.
- جرّب أولًا على **نسخة** من البيانات داخل تخزين جديد. لا تربط تطبيقين يكتبان إلى القاعدة نفسها أثناء الاختبار.
- ترحيل V8 إضافي: يضيف حقول اللغات والمرفقات والخدمات، ويحتفظ بالجداول والسجلات والأعمدة القديمة.
- تحديث V8 لا يترجم تلقائيًا نصوص المشاريع القديمة. أضف الترجمة من الإدارة؛ الواجهة تحافظ على النص المتاح عند غياب ترجمة المحتوى.

لإنشاء نسخة من مجلد بيانات موجود، استخدم بيئة تحتوي Python وملفات المشروع:

```bash
python scripts/backup.py --data-dir /actual/data/path --output /safe/backups/sami-before-v8.zip
```

أو داخل الحاوية الحالية بعد توفير السكربت:

```bash
docker compose exec web python scripts/backup.py --data-dir /app/data --output /app/data/backup-before-v8.zip
docker compose cp web:/app/data/backup-before-v8.zip ./backup-before-v8.zip
```

استخدم اسمًا جديدًا لكل نسخة. احفظ النسخة خارج الحاوية وفي مكان محمي لأنها تضم بيانات العملاء. السكربت يشمل `site.db` و`uploads/` و`attachments/`، ولا يضم ملف البيئة؛ احفظ إعدادات البيئة منفصلًا بطريقة آمنة.

## 3. تشغيل نسخة جديدة محليًا

1. فك ZIP داخل مجلد جديد.
2. انسخ `.env.example` إلى `.env`.
3. ولّد قيمة قوية لـADMIN_TOKEN:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

4. ضع القيمة في `.env`، دون علامات اقتباس ضرورية، ولا تشارك هذا الملف.
5. شغّل:

```bash
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --build
```

6. افتح http://localhost:8000 وhttp://localhost:8000/admin. النسخة المحلية تربط المنفذ على 127.0.0.1 فقط. إن كان مشغولًا غيّر LOCAL_PORT في `.env` وافتح المنفذ الجديد.
7. افحص:

```bash
docker compose logs --tail=100 web
curl http://localhost:8000/api/health
```

`HTTPS_ONLY=false` موجود فقط في override المحلي. لا تستخدمه على الدومين العام.

## 4. إعداد n8n بدون تغيير العقد الحالي

| المتغير | الاستخدام |
|---|---|
| `SAMI_N8N_WEBHOOK_URL` | Production Webhook للمساعد، POST |
| `SAMI_N8N_API_KEY` | يُرسل في ترويسة `X-SAMI-AI-KEY` |
| `SAMI_N8N_REQUESTS_URL` | Webhook اختياري لتنبيه الطلبات |
| `SAMI_N8N_REQUESTS_KEY` | مفتاح تنبيه الطلبات في الترويسة نفسها |

المساعد يستمر بإرسال:

```json
{"message":"...","sessionId":"..."}
```

والاستجابة المقبولة:

```json
{"reply":"نص الرد"}
```

أو `output` بدل `reply`. لا تضع مفاتيح Gemini أو Qdrant في JavaScript أو Git؛ تبقى في Credentials داخل n8n. لم تُرفق Workflow أو إعدادات Qdrant الحالية؛ الحفاظ هنا على عقد الاتصال، وليس إثبات أن خدمة السيرفر تعمل.

تحليل الأفكار يستعمل الـWebhook نفسه ويطلب JSON داخل `reply` بهذه المفاتيح فقط:

```json
{"summary":"...","problem":"...","solution":"...","components":["..."],"integrations":["..."],"workflow":["..."],"phases":["..."],"questions":["..."]}
```

كل قيمة نص أو قائمة نصوص. إن كانت تعليمات وكيل n8n تجبره على رد محادثة عادي، عدّل تعليماته لاحترام JSON عندما تطلبه الرسالة؛ دون تغيير عنوان Webhook. الرد غير المطابق أو المحتوي معلومات مالية يُرفض وتظهر رسالة إعادة المحاولة؛ لا تُعرض نتائج مختلقة.

عناوين HTTPS مدعومة. HTTP الداخلي مدعوم لاسم خدمة يبدأ بـ`n8n-` على المنفذ 5678 وشبكة Docker مشتركة. لا تفتح منفذ n8n إلى الإنترنت بسبب هذا الربط.

تنبيه الطلب يُرسل بعد الحفظ ويضم id وبيانات الطلب وhas_attachment، وليس بايتات المرفق. أعد JSON من Webhook الطلبات. فشل التنبيه لا يفقد الطلب؛ يظهر في الإدارة ولا توجد إعادة إرسال تلقائية. ملاحظات المعرفة المحلية محفوظة للإدارة، ولا تزامن تلقائيًا إلى Qdrant.

## 5. النشر على Coolify — بعد الموافقة فقط

1. أنشئ تطبيق اختبار جديدًا أو راجع إعدادات تطبيق v7 الحالي بعناية. لا تختَر تطبيق الدومين الأساسي.
2. اختر فرع التطوير، البناء Dockerfile ومسار Dockerfile الجذر.
3. اضبط المنفذ الداخلي **8000**. لا يلزم Host Port مثل 8087. ملف Compose الأساسي يستخدم expose فقط.
4. أضف الدومين `https://v7.samideveloper.com` إلى تطبيق v7 وحده، وتحقق من عدم ارتباطه بتطبيق آخر قبل التحويل.
5. أضف متغيرات `.env.example` في واجهة البيئة: ADMIN_TOKEN وHTTPS_ONLY=true وDATABASE_PATH=/app/data/site.db وSITE_URL=https://v7.samideveloper.com، ثم متغيرات n8n الحالية.
6. اربط تخزينًا دائمًا عند `/app/data`. للاختبار استعمل نسخة من البيانات الحالية لا التخزين الحي نفسه.
7. عند استخدام Compose، اسم Volume النهائي يتأثر باسم مشروع Compose؛ نقل المجلد قد ينشئ Volume جديدًا فارغًا. لا تعتبر ظهور صفحة فارغة فقدانًا للبيانات: راجع التخزين قبل أي حذف.
8. إن أردت استخدام Volume موجود عن قصد، ملف `docker-compose.existing-volume.yml` يطلب اسمه الدقيق عبر EXISTING_DATA_VOLUME. استخدمه فقط بعد النسخ والتحقق؛ لا تخمّن الاسم.
9. لا تضبط ثقة ترويسات Proxy لجميع مصادر الإنترنت. اجعل الوصول المباشر إلى الحاوية خاصًا، واضبط عناوين البروكسي الموثوقة وفق شبكة Coolify؛ Rate limit داخل التطبيق يعتمد على عنوان العميل الذي يراه Uvicorn.
10. عند الموافقة على النشر ابنِ وشغّل، ثم أكمل قائمة التحقق أدناه.

## 6. فحص ما بعد النشر

- health يرجع ok وV8، والموقع الأساسي لم يتغير.
- تسجيل الإدارة عبر HTTPS، Cookie تحمل HttpOnly وSecure وSameSite=Strict.
- تبديل AR/EN والاتجاه والثيم في الرئيسية والإدارة والهاتف.
- إضافة مشروع باللغتين، رفع صورة، تعديلها وإخفاء المشروع ثم حذفه التجريبي.
- إضافة مقالة وخدمة وتعديل نص الصفحة وروابط الموقع.
- طلب حقيقي تجريبي ببريد صحيح ومرفق؛ ظهور الطلب والمرفق في الإدارة وتغيير الحالة.
- محاولة فتح المرفق خارج جلسة الإدارة يجب أن تفشل.
- إعادة تشغيل التطبيق والتحقق من بقاء البيانات والصور والمرفقات.
- المساعد وتحليل الفكرة وPlayground مع n8n الحقيقي، والتحقق من Gemini/Qdrant داخل سجل n8n.
- فشل n8n التجريبي: الطلب محفوظ مع حالة تنبيه failed، وAI يعرض خطأ واضحًا.
- تحقق من اتجاه وتباين جميع أقسام الصفحة وغياب overflow على الهاتف.

## 7. الرجوع الآمن

احفظ صورة التطبيق/Commit السابق والنسخة الاحتياطية وإعدادات التخزين قبل الترقية. إذا فشل الاختبار أوقف نسخة V8، وأعد التطبيق السابق مع نسخة البيانات السابقة في تخزين منفصل. لا تكتب فوق البيانات الجديدة قبل تصدير الطلبات التي وصلت أثناء الاختبار. لا تشغّل أمر `docker compose down -v` ولا تحذف Volume أو SQLite. لا تحتاج الحزمة إلى أي حذف للبيانات.

## 8. ملاحظات تشغيل واقعية

عامل واحد Uvicorn مناسب لـSQLite وحدّ الطلبات داخل الذاكرة. إذا وسعت إلى عدة عمليات/نسخ، استخدم حد طلبات مشتركًا على البروكسي أو Redis. حد الرفع 5MiB لكل ملف، ويفضل ضبط حد جسم الطلب 6MiB على البروكسي أيضًا. الصور تُفحص وتُعاد صياغتها WebP؛ PDF يُخزن خاصًا ويُنزل كملف ولا يُنفّذ، وليس هناك ماسح فيروسات مرفق. غيّر ADMIN_TOKEN لإبطال الجلسات الموقّعة القديمة عند الحاجة.
